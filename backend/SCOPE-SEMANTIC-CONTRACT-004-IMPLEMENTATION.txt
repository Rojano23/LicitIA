3. THE FIVE ARCHITECT-DEFINED CLASSIFICATION RULES
========================================================================================================================

RULE 1: EXECUTION SCOPE GATE
  Purpose: First semantic decision before domain classification
  Question: Does this fragment establish an obligation that governs CONTRACT EXECUTION?
  NO  → return no obligation
  YES → proceed to RULE 2

  Explicitly excludes (even with mandatory language):
    • Bidder qualification (experience, certifications)
    • Proof of experience (constancias, cartas)
    • Proposal submission requirements
    • Procurement forms
    • Corporate/legal documentation
    • Tax documentation
    • Certificates required for participation
    • Registry participation and registration
    • Bidder declarations/manifests
    • Documents before award/formalization
    • Evidence used ONLY to prove eligibility/qualification

  CRITICAL: Do NOT filter by document type. An administrative document may
  contain a real execution obligation. Classify the OBLIGATION, not the document.

RULE 2: DOMAIN DECISION RULES — EXACTLY NINE DOMAINS
  After RULE 1 YES, classify to EXACTLY one of:

  1. TECHNICAL
     → technical procedures, specifications, inspection, maintenance, configuration,
       measurements, criteria, parameters, performance requirements

  2. SERVICE
     → service/action to perform, execution duration/timeframe, frequency,
       or general service execution condition

  3. SUPPLY
     → materials, consumables, spare parts, products consumed/incorporated
       during execution

  4. TOOLS_EQUIPMENT
     → equipment, tools, machinery, software, computing resources,
       communication devices, or other execution resources

  5. PERSONNEL
     → execution personnel: required roles, headcount, specialization,
       competency, professional qualification, experience
       (NOT proof of bidder qualification)

  6. SSPA
     → occupational safety, health, environmental protection, work permits,
       hazard/risk prevention, training, PPE, hygiene, controls
       (remains SSPA even with procedures, documentation, technical detail)

  7. DELIVERABLE
     → output to produce/deliver/hand over: report, record, dossier, drawing,
       test result, operational documentation generated by execution
       (NOT procurement/proposal/eligibility documents)

  8. LOGISTICS_SITE
     → physical execution location, site access, mobilization, transportation,
       demobilization, site logistics, physical movement/storage/access
       (NOT merely 'happens before work starts' or 'at the site')

  9. OTHER
     → ONLY for real execution-scope obligation that fits NONE of above 8
       (NOT a fallback or uncertainty catchall)

RULE 3: OTHER MUST NEVER HIDE NON-SCOPE
  Purpose: Prevent misuse of OTHER as default for ambiguous text
  Decision sequence:

  STEP 1: Is this actual execution scope?
          NO  → emit nothing
          YES → continue

  STEP 2: Which specific execution domain applies?
          TECHNICAL/SERVICE/SUPPLY/TOOLS_EQUIPMENT/PERSONNEL/SSPA/DELIVERABLE/LOGISTICS_SITE
          → emit with specific domain

  STEP 3: Only if NONE fits, but IS definitely execution scope
          → OTHER

  Forbidden patterns:
    • uncertain → OTHER
    • mandatory administrative language → OTHER
    • documentation mentioned → DELIVERABLE

RULE 4: CONTRACTUAL ATOMICITY
  Purpose: Govern obligation granularity
  Core: Every output obligation MUST represent exactly ONE independently
        meaningful contractual commitment

  SPLIT when the same source contains multiple INDEPENDENT obligations:
    • belong to different domains
    • could be independently complied with
    • could independently fail
    • require different resources/actions

  DO NOT split one obligation into every descriptive detail.
  DO NOT over-group multiple independent obligations.

  Guiding question:
  'Could this candidate reasonably be reviewed as a separate
   contractual commitment?'

  Example: 'obtain work permit, use specialized crew, follow maintenance'
           → 3 independent obligations (split)

  Example: 'hygiene standard: inspection, temperature control, storage rotation'
           → likely 1 obligation (grouping, unless each is independently
             enforceable)

RULE 5: EVIDENCE MUST BE VERBATIM
  Purpose: Ground all obligations in exact source text
  Requirement: evidence_excerpt MUST be
    • copied VERBATIM from SOURCE_TEXT
    • contiguous (no gaps, no reconstruction from non-adjacent spans)
    • non-empty
    • sufficient to support the obligation
    • not paraphrased
    • not corrected
    • not translated
    • not normalized by the model
    • not combined from non-contiguous spans

  Preserve source spelling, punctuation, wording.
  Description MAY normalize semantically.
  Evidence MUST remain verbatim grounded.
  Do not invent unsupported evidence.
  If no contiguous verbatim evidence supports obligation → DO NOT emit.
